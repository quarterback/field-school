# After action record: WCAG 2.2 AA built into the portal

**Date:** November 17, 2026
**Scope:** `east-detroit/prototype/portable` (all screens), plus `.github/workflows/east-detroit-a11y.yml`.

## What was asked

Build WCAG compliance into My East Detroit, following the public homepage redesign earlier the same day.

## What changed

- **Automated check.** `npm run check:a11y` (`scripts/a11y-check.mjs`) serves the built site and scans 16 screens at 1280px and 320px: the homepage, homepage search with no match, sign in, sign in error, five portal pages and seven walkthrough stops. It runs axe-core with the WCAG 2.0, 2.1 and 2.2 A and AA rules, plus custom checks for reflow (1.4.10), text spacing (1.4.12), target size (2.5.8), focus visible (2.4.7) and focus not obscured (2.4.11). New dev dependencies: `axe-core`, `puppeteer-core`.
- **CI.** The `east-detroit-a11y` workflow runs build and check on every push and pull request that touches this folder.
- **Rules.** `ACCESSIBILITY.md` sets WCAG 2.2 AA as the bar, lists the built in rules and the manual checks. `AGENTS.md` rule 8 and `CONTENT_STANDARDS.md` acceptance check 6 now require the check.

## Failures found and fixed

| Problem | WCAG | Screens | Fix |
| --- | --- | --- | --- |
| Header home button's `aria-label` did not contain its visible text | 2.5.3 | All 32 runs | Removed the `aria-label`; the visible name now reads "East Detroit City and County Services" with a hidden "home" after it |
| Page scrolled sideways at 320px (445px and 568px wide) | 1.4.10 | Portal home, Account and privacy, walkthrough home | Hidden "Action" header text inside tables was positioned against the page, not the table's scroll box. `.table-scroll` is now `position: relative` |
| Signed in header (Explore demo, My account, Sign out) ran off screen at 320px | 1.4.10 | Portal screens | Header row and actions wrap below 560px |
| Every screen had the same page title | 2.4.2 | All | `document.title` now follows each screen's `h1` |
| Focus stayed on the old control after moving to a new screen | 2.4.3 | All navigation | Focus moves to the new screen's `h1` |
| Homepage search scrolled smoothly regardless of motion settings, and focus did not follow | 2.3.3 (AAA, adopted), 2.4.3 | Homepage | Honors `prefers-reduced-motion`; focus moves to the results section |
